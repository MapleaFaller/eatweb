# 交我吃 · 三食堂门店菜单（ver0.2 · 本地文件版）

一个原生 HTML + CSS + JavaScript 的展示型网页项目：**菜品数据与菜品图片全部直接调用本地
文件**（正餐 `data/*.xlsx` + `images/`，早餐 `data/breakfast/*.xlsx` + `images-breakfast/`，
均为多级中文目录），无需数据库、无需后端服务，
只需把项目放到本地 HTTP 服务器下打开即可（浏览器安全限制：用 `file://` 直接双击打开
无法读取 xlsx，见下文「如何运行」）。

左侧为导航菜单（公告 / 今天吃什么 / 三个食堂），右侧为内容区（公告板、食堂介绍、
菜品网格、随机推荐），点击菜品卡片可弹出详情模态框。

## 数据流（本版核心改动）

1. **正餐清单**：`data/First.xlsx`、`Second.xlsx`、`Third.xlsx`
   （每个食堂一个 xlsx）——页面启动时用浏览器内置的 SheetJS（`js/lib/xlsx.full.min.js`）
   直接解析这些本地 xlsx 文件得到每个餐厅的菜单。
2. **正餐图片**：`images/` 下按「食堂名 → 楼层标签 → 门店名 → 菜名」多级目录存放
   的 `.png/.svg` 等文件（如 `images/第一食堂/2F · 家常/家味小厨/红烧肉.svg`），
   页面按该路径加载本地图片；无对应图片时显示灰色占位图。
3. **早餐数据**：`data/breakfast/First.xlsx`、`Second.xlsx`、`Third.xlsx`
   （格式与正餐表完全相同）提供各窗口早餐，图片放在 `images-breakfast/`
   （结构与 `images/` 相同）。页头右上角可切换「正餐 / 早餐」；
   **早餐表里没有出现的窗口 = 该窗口「无早餐」**，页面会明确提示。
4. **食堂/楼层/门店骨架**（名称、简介、图标、店招等静态文案）仍在 `js/data.js`，
   加载时按“餐厅名”与 xlsx 内容对应合并；门店清单本身以 xlsx 里出现的顺序为准。

## xlsx 表格格式（重要）

- **一个食堂一个 xlsx**：`First.xlsx` = 第一食堂，`Second.xlsx` = 第二食堂，
  `Third.xlsx` = 第三食堂。
- **一个楼层一个 sheet，且顺序 = 楼层顺序**：第 1 个 sheet = 一楼、第 2 个 sheet = 二楼……
  （如 `First.xlsx` 的第 2 个 sheet 就是第一食堂二楼）。
- **每个 sheet 的表头**：`餐厅 | 名称 | 价格 | 介绍`，从**第 2 行**起一行一道菜；
  同一餐厅的菜连续排在一起（A 列写同一餐厅名，页面据此把菜分回各家店）。
- 例：**第一食堂二楼第一个餐厅第一道菜** 的信息在 `First.xlsx` 的 sheet2 中
  **第二列第二行（B2）**，其名称在 B2、价格在 C2、介绍在 D2，A 列为该餐厅名。
- 「价格」一格请填**数字**（如 `48`），不要带 “元/¥”，可带小数。
- 「介绍」可有可无，留空时页面显示“暂无描述”。

在 Excel / WPS 里改好表格、保存后**刷新页面即生效**。

## 菜品图片（images/ 多级目录结构）

菜品图片统一放在 `images/` 下，按「食堂 → 楼层 → 门店 → 菜」四级中文目录归档，
一眼就能看出每张图属于哪家店哪道菜：

```
images/
├── 第一食堂/
│   ├── 1F · 风味/
│   │   ├── 川味小馆/水煮鱼.svg、辣子鸡.svg …
│   │   └── 粤式茶点/虾饺.svg、肠粉.svg …
│   └── 2F · 家常/
│       └── 家味小厨/红烧肉.svg、清蒸鲈鱼.svg …
├── 第二食堂/ …
└── 第三食堂/ …
```

- 第 1 级「食堂名」：第一食堂 / 第二食堂 / 第三食堂（与 `js/data.js` 中的食堂名一致）；
- 第 2 级「楼层标签」：与 `js/data.js` 中该楼层的 `label` 一致（如 `2F · 家常`，含空格）；
- 第 3 级「门店名」：即 xlsx 中该店在 A 列的店名；
- 文件名「菜名」：即 xlsx 中该菜在 B 列的“名称”，如 `红烧肉.svg`。
  目前各店目录里已生成 svg 占位示例图（图上标有该菜的内部编号与菜名/价格）。

图片查找：页面会**一次性并行探测**同名候选文件，自动使用优先级最高的可用项
（`png → jpg → jpeg → webp → svg`，同时兼容大写 `.PNG/.JPG`）。所以
**只要把真实照片放进对应门店目录、文件名与该菜名相同**，例如
`images/第一食堂/2F · 家常/家味小厨/红烧肉.png`，页面会自动优先显示真实照片，
无需改任何代码；没有真实照片时显示该目录下的 svg 占位示例图。

注意：图片按“名称”对应——在 xlsx 里改了菜名 / 店名，或在 `js/data.js`
改了楼层标签后，请**同步把对应图片文件 / 目录改成一致的新名称**，
否则页面会找不到图片（只显示灰色占位图）。

早餐图片放在隔壁的 `images-breakfast/` 目录，结构、命名与优先级规则完全相同
（详见下文「早餐模式」）。

## 早餐模式（页头右上角「正餐 / 早餐」切换）

页头右上角有一个「正餐 / 早餐」切换按钮：

- **正餐**（默认）：展示 `data/*.xlsx` + `images/` 的常规菜单；
- **早餐**：展示 `data/breakfast/*.xlsx` + `images-breakfast/` 的早餐菜单，
  左侧边栏的营业时间同步变为早餐时段，菜单里的数量徽标也会变成早餐数量。

早餐表的组织方式与正餐表完全一样（一个食堂一个 xlsx、一个楼层一个 sheet、
表头 `餐厅 | 名称 | 价格 | 介绍`），只是放在 `data/breakfast/` 目录：

```
data/breakfast/
├── First.xlsx      # 第一食堂早餐
├── Second.xlsx     # 第二食堂早餐
└── Third.xlsx      # 第三食堂早餐
```

**「无早餐」规则（重要）**：某家门店只要**没有出现在早餐表里**
（该楼层 sheet 中没有以它店名为 A 列的行块），就视为该窗口不供应早餐——
切到早餐模式后：

- 左侧菜单中该门店显示「无早餐」徽标；
- 右侧菜品目录位置显示「本窗口无早餐」提示（并提示可切换窗口或切回正餐）。

早餐图片放在 `images-breakfast/` 下，目录结构与 `images/` 完全一致：

```
images-breakfast/第一食堂/2F · 家常/家味小厨/现磨豆浆.svg
images-breakfast/第一食堂/2F · 家常/家味小厨/现磨豆浆.png   ← 真实照片优先
```

**给某窗口增加早餐**：在对应 `data/breakfast/*.xlsx` 的楼层 sheet 末尾按正餐
写法追加一个行块（A 列写该店店名），再把早餐照片按
`images-breakfast/<食堂名>/<楼层标签>/<门店名>/<菜名>.png` 放好即可。
**要让某窗口变成「无早餐」**：把它的行块从早餐表中删掉并保存即可（不影响正餐）。
早餐表的增删改与正餐表操作完全一致，参见下文「如何维护」。

## 如何运行（重要）

浏览器有安全限制：直接双击 `index.html`（`file://` 方式）能显示本地图片，但
**无法读取本地 xlsx**。请用本地 HTTP 服务器方式打开：

1. **双击 `start-server.bat`（推荐）**
   - 优先用 Node.js 启动（你的机器上 `python` 命令可能是“Windows 应用商店别名”，
     有时会静默失败导致服务没起来——本脚本会自动跳过并改用 Node / 本地 Python）；
   - 自动寻找空闲端口（默认 8000，被占用则用 8001…），服务就绪后自动打开浏览器；
   - **弹出一个黑色窗口即服务器窗口，请保持开启**；关闭它服务即停止。
2. 手动命令行（在本目录下，任选其一）：
   - `node server.js`，然后访问 `http://127.0.0.1:8000/`，或
   - `python -m http.server 8000`，然后访问 `http://127.0.0.1:8000/`。

如果浏览器提示打不开：
- 先确认服务器黑色窗口仍在（窗口里应有“服务器已启动”字样）；
- 在浏览器手动输入 `http://127.0.0.1:8000/`（不要用 `file://` 打开页面）；
- 若端口被占用或首次运行被防火墙询问，允许访问或换端口即可。

页面顶部会显示数据源状态条（“数据源就绪…/ 读取失败原因”），方便排查。

## 脚本加载顺序（重要）

脚本之间通过全局变量/函数协作，必须按下述顺序加载（`index.html` 中已排好）：

```
data.js → utils.js → state.js → xlsx.full.min.js → loader.js
       → menu.js → views.js → modal.js → index-panel.js → app.js
```

- `data.js` 提供骨架 → `loader.js` 在 `app.js` 启动时异步读取本地 xlsx 并填充菜品、
  解析本地菜品图片；其余渲染模块（menu/views/modal）基于加载完成后的数据工作；
- `app.js` 最后执行：先显示“读取中”，数据就绪后渲染，并在顶部给出成功/失败提示。

下表是“速查”，三个常用维护操作（**修改菜品信息 / 添加新菜品 / 添加新门店**）的
分步文字说明见下（示例以第一食堂为例，其余食堂操作相同）。

> 早餐表的维护方式与正餐表**完全一致**，只是文件在 `data/breakfast/` 下、
> 图片放在 `images-breakfast/` 下；把某店的行块从早餐表删掉 = 该窗口「无早餐」。

### 1. 修改菜品信息（改菜名 / 改价格 / 改介绍）

1. 用 Excel / WPS 打开对应食堂的 xlsx：第一食堂开 `data/First.xlsx`、
   第二食堂开 `data/Second.xlsx`、第三食堂开 `data/Third.xlsx`。
2. 切到该菜所在楼层的 sheet（第 1 个 sheet = 一楼、第 2 个 sheet = 二楼……），
   在表头 `餐厅 | 名称 | 价格 | 介绍` 四列里找到这道菜所在的行。
3. 直接改对应单元格：**B 列 = 菜名、C 列 = 价格、D 列 = 介绍**。
   价格一格填数字即可（如 `58`，不要带“元/¥”，可带小数）；
   介绍可有可无，留空时页面显示“暂无描述”。
4. 保存文件后**刷新页面即生效**（服务器窗口不用重启）。

注意：**A 列店名不要动**——A 列决定这道菜属于哪家店，改了就相当于把菜“搬”到别的店。
改「名称」后请同步把该菜的图片文件名改成一致的新菜名（价格与介绍不影响图片），
页面才能继续找到这张图。

### 2. 添加新菜品（给某家已有门店加一道菜）

1. 打开该食堂的 xlsx，切到该门店所在楼层的 sheet。
2. 找到这家店在 A 列的连续行块（同一家店的菜必须连在一起排）。
3. 在该店行块的**最后一行下方**新增一行，依次填写：
   - A 列 = 店名（与这家店其它行**一字不差**）；
   - B 列 = 新菜名；C 列 = 价格（数字）；D 列 = 介绍（可留空）。
4. 保存并刷新页面，新菜即出现在这家店菜单末尾。

图片方面无需额外操作：新菜暂时没有图片时，页面自动显示灰色占位图。
想配真实照片的话，把照片放进**该店目录**、文件名 = 新菜名即可，例如给
「家味小厨」加一道“干锅土豆片”后放入：
`images/第一食堂/2F · 家常/家味小厨/干锅土豆片.png`
（png/jpg/webp 均可，png 优先；没有照片就不放文件，页面显示占位图）。

注意：
- **新行务必加在该店行块的末尾**（同一家店的菜保持连在一起），菜单顺序才正确。
- **B 列必须有菜名、A 列必须写对店名**：菜名为空的行会被自动跳过；
  A 列店名写错或留空，会被当成另一家新店。
- 店块之间可留空行做分隔，空行会被自动跳过，不影响读取。

### 3. 添加新门店（在某楼层新增一家店）

> 菜单里的门店清单以 xlsx 中出现的顺序为准，所以**新增门店必须先在 xlsx 里加数据**，
> 只改 `js/data.js` 不会生效。

1. 打开该食堂的 xlsx，切到想放新店的楼层 sheet。
2. 滚动到该楼层**最后一家店行块的下方**，另起一个新的行块：
   - 第一行 A 列写新店店名；
   - 之后每一行写一道该店的菜（这些行的 A 列都写同一个新店名）；
   - **新店至少要写 1 道菜**，否则页面不会生成这家店。
3. 保存并刷新页面：新店会出现在该楼层门店列表的**最后**。

为新店配图（可选）：新店暂时没有图片时菜品显示灰色占位图。要配真实照片，
按目录规则为新店建好目录、把照片以菜名命名放进去即可，例如新店「山西面馆」
的第一道菜「油泼面」：`images/第一食堂/2F · 家常/山西面馆/油泼面.png`
（没有真实照片时，也可复制一张现有的 svg 占位图改名为菜名放入，即可显示占位样式）。
店名在该楼层 sheet 内建议保持唯一，重名会导致两家店的数据混在一起。

（可选）在 `js/data.js` 中给新店补充简介 / 图标 / 店招横幅：
打开 `js/data.js`，在该食堂对应楼层的 `shops` 数组里追加一个门店对象
（参照同层已有门店的写法）。`name` 必须与 xlsx 中 A 列的店名**一字不差**
（页面按店名匹配元信息）：

```js
{
    id: 'c1f2s3',                  // 唯一 id，不与现有门店重复即可
    name: '新店名',                // ★ 必须与 xlsx 里 A 列的店名完全一致
    desc: '一句话简介',            // 不填则用默认简介文案
    icon: 'fa-utensils',           // FontAwesome 图标类名，可省略（自动分配默认图标）
    image: 'https://picsum.photos/seed/c1f2s3/900/300', // 店招横幅图，可省略
    items: []                      // 菜品不需要在这里填，xlsx 会自动填充
}
```

保存刷新后：xlsx 中同名的店会与这段配置合并——简介 / 图标 / 店招用你填的，
没填的字段用默认值（店招默认按门店 id 自动生成 picsum 占位图，需联网，
加载失败时自动显示灰色占位）。

- 部分食堂/门店的“宣传大图”（介绍页轮播图、菜单页店招横幅）仍使用 `picsum.photos`
  网络占位图，需要联网；加载失败时页面会自动显示灰色占位，不影响菜品展示。
- 手机端体验与旧版一致：≤768px 时顶部出现「索引」按钮，点开下拉抽屉导航。
