# 交我吃 · 三食堂门店菜单（ver0.2 · 本地文件版）

一个原生 HTML + CSS + JavaScript 的展示型网页项目：**菜品数据与菜品图片全部直接调用本地
文件**（`data/*.xlsx` 菜品表 + `images/*` 菜品图片），无需数据库、无需后端服务，
只需把项目放到本地 HTTP 服务器下打开即可（浏览器安全限制：用 `file://` 直接双击打开
无法读取 xlsx，见下文「如何运行」）。

左侧为导航菜单（公告 / 今天吃什么 / 三个食堂），右侧为内容区（公告板、食堂介绍、
菜品网格、随机推荐），点击菜品卡片可弹出详情模态框。

## 数据流（本版核心改动）

1. **菜品清单**：`data/First.xlsx`、`Second.xlsx`、`Third.xlsx`
   （每个食堂一个 xlsx）——页面启动时用浏览器内置的 SheetJS（`js/lib/xlsx.full.min.js`）
   直接解析这些本地 xlsx 文件得到每个餐厅的菜单。
2. **菜品图片**：`images/<图片序号>.png/.svg` 等——图片序号即该菜在
   「食堂号 + 楼层号 + 餐厅号 + 菜序号」中的编号，页面按序号加载本地图片。
3. **食堂/楼层/门店骨架**（名称、简介、图标、店招等静态文案）仍在 `js/data.js`，
   加载时按“餐厅名”与 xlsx 内容对应合并；门店清单本身以 xlsx 里出现的顺序为准。

## xlsx 表格格式（重要）

- **一个食堂一个 xlsx**：`First.xlsx` = 第一食堂，`Second.xlsx` = 第二食堂，
  `Third.xlsx` = 第三食堂。
- **一个楼层一个 sheet，且顺序 = 楼层顺序**：第 1 个 sheet = 一楼、第 2 个 sheet = 二楼……
  （如 `First.xlsx` 的第 2 个 sheet 就是第一食堂二楼）。
- **每个 sheet 的表头**：`餐厅 | 名称 | 价格 | 介绍`，从**第 2 行**起一行一道菜；
  同一餐厅的菜连续排在一起（A 列写同一餐厅名，页面据此把菜分回各家店）。
- 例：**第一食堂二楼第一个餐厅第一道菜** 的信息在 `First.xlsx` 的 sheet2 中
  **第二列第二行（B2）**，其名称在 B2、价格在 C2、介绍在 D2，A 列为该餐厅名。
- 「价格」一格请填**数字**（如 `48`），不要带 “元/¥”，可带小数。
- 「介绍」可有可无，留空时页面显示“暂无描述”。

在 Excel / WPS 里改好表格、保存后**刷新页面即生效**。

## 图片序号（images/ 目录命名）

```
图片序号 = 食堂号 + 楼层号 + 餐厅号 + 菜序号      （按十进制直接拼接）
```

- 食堂号：第一/第二/第三食堂 = 1 / 2 / 3
- 楼层号：取楼层标签里的数字（“2F · 家常” → 2）
- 餐厅号：该楼层里第几个餐厅（按 xlsx 中出现顺序，1 起）
- 菜序号：该餐厅内第几道菜（按 xlsx 行顺序，1 起）

示例：**第一食堂 二楼 第 1 餐厅 第 1 道菜 → `1211`**（已生成示例图
`images/1211.svg`，图内同时标出“示例图 #1211”与菜名/价格）。

图片查找顺序：同名文件 `png → jpg → jpeg → webp → svg`。
所以**只要放入真实照片 `images/1211.png`，页面会自动优先显示真实照片**，
无需改任何代码；没有对应图片的菜显示“暂无图片”占位。

## 如何运行（重要）

浏览器有安全限制：直接双击 `index.html`（`file://` 方式）能显示本地图片，但
**无法读取本地 xlsx**。请用本地 HTTP 服务器方式打开：

1. **双击 `start-server.bat`（推荐）**
   - 优先用 Node.js 启动（你的机器上 `python` 命令可能是“Windows 应用商店别名”，
     有时会静默失败导致服务没起来——本脚本会自动跳过并改用 Node / 本地 Python）；
   - 自动寻找空闲端口（默认 8000，被占用则用 8001…），服务就绪后自动打开浏览器；
   - **弹出一个黑色窗口即服务器窗口，请保持开启**；关闭它服务即停止。
2. 手动命令行（在本目录下，任选其一）：
   - `node server.js`，然后访问 `http://127.0.0.1:8000/`，或
   - `python -m http.server 8000`，然后访问 `http://127.0.0.1:8000/`。

如果浏览器提示打不开：
- 先确认服务器黑色窗口仍在（窗口里应有“服务器已启动”字样）；
- 在浏览器手动输入 `http://127.0.0.1:8000/`（不要用 `file://` 打开页面）；
- 若端口被占用或首次运行被防火墙询问，允许访问或换端口即可。

页面顶部会显示数据源状态条（“数据源就绪…/ 读取失败原因”），方便排查。

## 脚本加载顺序（重要）

脚本之间通过全局变量/函数协作，必须按下述顺序加载（`index.html` 中已排好）：

```
data.js → utils.js → state.js → xlsx.full.min.js → loader.js
       → menu.js → views.js → modal.js → index-panel.js → app.js
```

- `data.js` 提供骨架 → `loader.js` 在 `app.js` 启动时异步读取本地 xlsx 并填充菜品、
  解析本地菜品图片；其余渲染模块（menu/views/modal）基于加载完成后的数据工作；
- `app.js` 最后执行：先显示“读取中”，数据就绪后渲染，并在顶部给出成功/失败提示。

## 如何维护（改数据 / 加菜 / 换图）

| 想做什么 | 怎么做 |
| --- | --- |
| 改菜名/价格/介绍 | 打开对应 `data/*.xlsx`，直接改单元格后保存并刷新页面 |
| 给某餐厅加一道菜 | 在该餐厅的连续行块末尾新增一行（A 列填餐厅名），保存刷新 |
| 新增一个餐厅 | 在该楼层 sheet 末尾新起一个行块，A 列写新餐厅名（可在 `js/data.js` 为该店补简介/图标） |
| 新增一个楼层 | 在对应食堂的 xlsx 末尾按楼层顺序加一个 sheet；并在 `js/data.js` 该食堂下加一个 floors 项 |
| 换真实菜品照片 | 把照片命名为图片序号放入 `images/`，如 `images/1211.png`（png/jpg/webp 均可，自动优先于示例图） |
| 重新生成全部示例数据 | `node dev-tools/build.js`（会重建 `data/*.xlsx` 与全部占位示例图，覆盖原内容） |

说明：
- 部分食堂/门店的“宣传大图”（介绍页轮播图、菜单页店招横幅）仍使用 `picsum.photos`
  网络占位图，需要联网；加载失败时页面会自动显示灰色占位，不影响菜品展示。
- 手机端体验与旧版一致：≤768px 时顶部出现「索引」按钮，点开下拉抽屉导航。

> 提示：`index.html` 是项目唯一入口；放到任意静态服务器上部署时默认首页即此文件。
